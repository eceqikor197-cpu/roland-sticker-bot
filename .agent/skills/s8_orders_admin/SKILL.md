# Этап S8: Сохранение дизайнов, заказы и связка с плоттером

## Контекст и правила
- Читай `AGENTS.md`, `docs/COORDINATES.md`, `docs/PROGRESS.md`.
- В MVP нет пользовательских загрузок картинок и нет онлайн-оплаты (заказы одобряются вручную).
- Клиент **НИКОГДА** не пишет в Hot Folder плоттера напрямую. Файл резки формируется и отправляется в Hot Folder **только после явного нажатия кнопки «Подтвердить» авторизованным оператором**.
- В тестах Hot Folder переопределяется на временную директорию `tmp_path`.
- Работа ведётся в ветке `feature/s8`.

## Задачи этапа
1. **База данных (`app.db`):**
   - Таблицы:
     - `designs`: `(id, share_token, object_id, design_json, created_at)`
     - `orders`: `(id, design_id, contact, status, price_estimate, status_token, created_at, updated_at)`
     - Статусы: `new`, `approved`, `queued`, `printed`, `done`, `rejected`.
     - `order_events`: `(id, order_id, event_type, details_json, created_at)` (аудит-лог).

2. **API клиентов:**
   - `POST /api/v1/designs`: сохранение дизайна (валидация по `design.schema.json`, проверка лимита до 150 стикеров, возврат `share_token`).
   - `GET /api/v1/designs/{share_token}`: загрузка ранее сохранённого дизайна по ссылке.
   - `POST /api/v1/orders`: оформление заказа (контакт: Telegram username или email).
   - `GET /api/v1/orders/{status_token}/status`: публичная страница проверки статуса заказа.

3. **Расчёт стоимости:**
   - Вызов функции через адаптер `calculate_nesting_and_price` из существующего кода.
   - Все тарифные сетки и коэффициенты читаются из конфигурации (`config.py` / `.env`), без захардкоженных цен.

4. **Панель оператора (Админка):**
   - Защита: авторизация через безопасные сессионные куки (HttpOnly, SameSite=Strict) с CSRF-защитой (сессии из Фазы 2). Пароли в URL запрещены.
   - Просмотр списка заказов и превью композиции.
   - Кнопки: «Подтвердить заказ», «Отклонить заказ», «Отправить в Hot Folder».
   - Идемпотентность: повторное нажатие «Подтвердить» не генерирует дублирующихся файлов в Hot Folder.

5. **Тесты (`tests/app/test_orders_workflow.py`):**
   - Полный сценарий: создание дизайна -> заказ -> авторизация оператора -> подтверждение -> появление файла в тестовой папке Hot Folder.
   - Попытка доступа к админским эндпоинтам без валидной сессии возвращает 401/403.
   - Валидация входных данных и обработка невалидных контактов.

## Критерий готовности
- Сквозной сценарий заказа с ручной модерацией и отправкой файла на плоттер протестирован.
- `python -m pytest -q` и `python -m ruff check .` зелёные.
- Результаты зафиксированы в ветке `feature/s8`, обновлён `docs/PROGRESS.md`.
