Фаза 3: авторизация и лимиты в Telegram-боте. Читай AGENTS.md.

Проблемы:
- Callback «job:<id>:hot:1» отправляет любое задание в Hot Folder плоттера для ЛЮБОГО пользователя, владелец задания не проверяется. Остальные job-callback'и тоже не проверяют владельца.
- В jpeg2eps.py стоит Image.MAX_IMAGE_PIXELS = None (защита от «бомб» отключена).
- Размер макета и растяжение ограничены только снизу; ввод вроде «2000 м» создаст гигантский файл.
- Нет лимитов на размер файла, частоту запросов и число одновременных конвертаций.
- Текст исключений показывается пользователю.

Задачи:
1. Во всех callback'ах job:* проверяй, что meta.json["user_id"] совпадает с call.from_user.id (админ может всё). Иначе ответ «Это не ваш макет» и выход.
2. Отправка в Hot Folder: по умолчанию разрешена только админам. Для обычных пользователей добавь режим «заявка»: создаётся запись «ожидает подтверждения», админ получает сообщение с кнопками «Подтвердить / Отклонить». Флаг ALLOW_USER_HOT_FOLDER=false по умолчанию.
3. Верни защиту PIL: MAX_IMAGE_PIXELS = 60_000_000 (настраивается), поймай DecompressionBombError и верни пользователю понятную ошибку.
4. Ограничения: размер входного файла (MAX_UPLOAD_MB=15), размер макета по большей стороне (MAX_SIZE_MM=1370 или по ширине рулона), коэффициенты растяжения (0.1–10). Применяй их и при кнопках, и при вводе текстом.
5. Лимит частоты: не более 6 конвертаций на пользователя в минуту и 1 одновременная конвертация на пользователя; глобально не более N (по умолчанию 2) через threading.Semaphore. Остальным показывай «в очереди».
6. Ошибки пользователю: общее сообщение «Не удалось обработать файл», а подробности в лог через logging.exception. Админу можно показывать детали.
7. Тесты на проверку владельца, лимиты размеров и поведение при превышении.

Критерий готовности: пользователь B не может ни изменить, ни отправить на плоттер макет пользователя A; тесты зелёные; отчёт по формату AGENTS.md.
