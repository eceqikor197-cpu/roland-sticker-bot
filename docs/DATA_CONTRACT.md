# Контракт данных: harvester.db и веб-сервис стикербомбинга

Документ фиксирует структуру базы данных `harvester.db`, назначение таблиц и полей, правила сопоставления путей и использование данных в веб-сервисе стикербомбинга (`sticker_app`).

---

## 1. Общие принципы

1. **Режим доступа:** `harvester.db` открывается сервисом **ТОЛЬКО** в режиме `read-only` (`sqlite3.connect('file:...harvester.db?mode=ro', uri=True)`). Сервис никогда не выполняет `INSERT`, `UPDATE`, `DELETE`, `ALTER` или создание таблиц в `harvester.db`.
2. **Собственные метаданные:** Все обогащённые данные (теги, палитры, эмбеддинги, статусы такдауна, пользовательские дизайны, заказы) сервис сохраняет в отдельную базу `app.db`.
3. **Файловые пути:** Сервис **НИКОГДА** не доверяет полям `local_*_path`, содержащим абсолютные пути файловой системы сервера harvester. Все пути строятся относительно переменной окружения `STORAGE_ROOT`.

---

## 2. Таблицы harvester.db

В базе `harvester.db` определены 5 таблиц:

| Таблица | Назначение в harvester | Использование в sticker_app |
|---|---|---|
| `assets` | Реестр готовых макетов (.eps, .png, размеры, контуры) | **Основной источник каталога** |
| `topics` | Очередь тем парсинга с категориями и поисковыми запросами | **Источник тегов и семантического поиска** |
| `phashes` | 64-битные перцептивные хеши для дедупликации картинок | Вспомогательный поиск дублей / похожих |
| `seen_urls` | История обработанных URL источников (Pinterest и др.) | **Игнорируется** (служебная для парсера) |
| `harvester_state` | Состояние воркера парсера (счётчики, heartbeat) | **Игнорируется** (служебная для воркера) |

## 3. Таблица `assets`: детальное описание полей

| Поле | Тип | Назначение в harvester | Роль в сервисе |
|---|---|---|---|
| `asset_id` | `TEXT PRIMARY KEY` | Уникальный 10-значный hex-идентификатор (напр., `e4a1b8c2d9`) | Основной публичный ID стикера |
| `topic_id` | `INTEGER` | Внешний ключ к `topics.id` | Связь с темой, получение поисковых запросов темы |
| `category_lvl1` | `TEXT` | Основная категория (`03_Одиночные_Стикеры`, `01_Стикерпаки` и др.) | Фильтр каталога (для холста по умолчанию `03_Одиночные_Стикеры`) |
| `category_lvl2` | `TEXT` | Подкатегория (напр., `Сериалы_и_Кино`, `Аниме`, `Мемы`) | Фильтрация в каталоге, генерация тегов |
| `folder_slug` | `TEXT` | Слаг папки темы (напр., `Cyberpunk_2077`) | Фильтрация, обогащение тегов |
| `topic_name` | `TEXT` | Название темы для отображения (напр., `Cyberpunk 2077`) | Отображение в UI, полнотекстовый поиск, теги |
| `asset_type` | `TEXT` | Тип макета (`single_sticker`, `pack_sheet`, `car_decal`, `banner`) | Фильтр (`single_sticker` для кастомайзера) |
| `title` | `TEXT` | Название макета | Полнотекстовый поиск, UI карточки |
| `source_name` | `TEXT` | Источник парсинга (`web`, `pinterest`, `yandex` и др.) | Метаданные происхождения |
| `source_url` | `TEXT` | Исходный URL страницы/картинки | Аудит авторских прав / takedown |
| `license` | `TEXT` | Лицензия (`own`, `licensed`, `cc0`, `unknown`) | Лицензионный фильтр (`LICENSE_FILTER`) |
| `uploaded_by` | `TEXT` | Автор загрузки (если загружен вручную) | Игнорируется в MVP |
| `phash_hex` | `TEXT` | 16-значный hex перцептивного хеша (64 bit) | Поиск визуально похожих / фильтрация дублей |
| `width_px` | `INTEGER` | Ширина исходного растра в пикселях | Расчёт пропорций (aspect ratio) |
| `height_px` | `INTEGER` | Высота исходного растра в пикселях | Расчёт пропорций (aspect ratio) |
| `width_mm` | `REAL` | Физическая ширина стикера в миллиметрах для плоттера | Базовый масштаб при добавлении на холст |
| `height_mm` | `REAL` | Физическая высота стикера в миллиметрах для плоттера | Базовый физический размер |
| `offset_mm` | `REAL` | Отступ контура реза CutContour в мм (обычно 2.5 мм) | Экспорт контура реза (S7) |
| `perf_cut_mode` | `TEXT` | Режим сквозного реза (`die_cut`, `sheet_frame`, `none`) | Используется при экспорте на плоттер |
| `num_contours` | `INTEGER` | Число векторных контуров CutContour в EPS | Контроль качества (1–2 для одиночного) |
| `eps_size_mb` | `REAL` | Размер файла .EPS в МБ | Служебное поле, игнорируется |
| `rel_folder_path` | `TEXT` | Относительный путь папки (`cat1/cat2/slug/sub_dir`) | **Критично:** построение безопасного пути на диске |
| `eps_filename` | `TEXT` | Имя готового файла EPS для плоттера | **Критично:** поиск EPS для экспорта (S7) |
| `png_filename` | `TEXT` | Имя исходного изображения (PNG/JPG) | **Критично:** генерация превью и отображение |
| `local_eps_path` | `TEXT` | Абсолютный путь к EPS на машине harvester | **Игнорируется** (непереносимый путь) |
| `local_png_path` | `TEXT` | Абсолютный путь к PNG на машине harvester | **Игнорируется** (непереносимый путь) |
| `local_preview_path` | `TEXT` | Абсолютный путь к превью на машине harvester | **Игнорируется** (непереносимый путь) |
| `gdrive_folder_path` | `TEXT` | Путь в Google Drive через rclone | Игнорируется сервисом |
| `synced_to_gdrive` | `INTEGER` | Флаг синхронизации с облаком | Игнорируется сервисом |
| `in_hot_folder` | `INTEGER` | Флаг отправки в Hot Folder плоттера harvester | Игнорируется сервисом (у сервиса своя очередь) |
| `parent_asset_id` | `TEXT` | ID родительского макета (стикерпака-листа) | Связь «стикер из пака» (см. разд. 5) |
| `created_at` | `REAL` | Время создания записи (unix timestamp) | Сортировка каталога (новинки) |

## 4. Таблица `topics`

Поля:
- `id` (`INTEGER PRIMARY KEY`): Уникальный ID темы.
- `category_lvl1`, `category_lvl2`: Иерархия категорий.
- `topic_name`: Человекочитаемое название темы (напр., `"Cyberpunk: Edgerunners"`).
- `folder_slug`: Уникальный слаг темы (`UNIQUE(category_lvl1, category_lvl2, folder_slug)`).
- `search_queries_json`: JSON-массив поисковых запросов темы (напр., `["cyberpunk edgerunners stickers", "lucy rebecca sticker png"]`). Используется модулем обогащения метаданных для формирования ключевых слов и тегов.
- `priority`, `is_enabled`, `harvest_cycles`, `items_count`, `packs_count`, `last_harvested_at`, `created_at`: Служебные поля планировщика парсера (в сервисе игнорируются).

## 5. Взаимосвязь EPS, PNG, Previews и parent_asset_id

### Файловая тройка макета
Каждый макет в каталоге представлен файлами:
1. **Исходный растр (`png_filename`)**:
   Оригинальное изображение высокого разрешения без сжатия (обычно с альфа-каналом прозрачности). Располагается по относительному пути:
   `STORAGE_ROOT / rel_folder_path / png_filename`
2. **Векторный файл для плоттера (`eps_filename`)**:
   PostScript EPS файл, созданный конвертером `jpeg2eps.py`. Содержит растровое изображение и векторный контур спот-цвета `CutContour` (и при необходимости `PerfCutContour`). Располагается по пути:
   `STORAGE_ROOT / rel_folder_path / eps_filename`
3. **Превью-изображения**:
   - `local_preview_path` в harvester хранил уменьшенный JPEG (max 780px).
   - Веб-сервис стикербомбинга генерирует собственные кэшированные превью с сохранением альфа-канала (`thumb` 256px WebP, `preview` 1024px WebP/PNG) в локальную директорию `CACHE_DIR`.

### parent_asset_id
- Поле предназначено для связи «стикерпак -> отдельные стикеры»: если целый лист `pack_sheet` разрезается на стикеры, каждый отдельный стикер получает запись в `assets` со ссылкой `parent_asset_id = <pack_sheet.asset_id>`.
- В текущей реализации конвейера парсера `eps_pipeline.py` резка листов отключена для сохранения качества оригиналов (`pack_sheet` остаётся единым листом), поэтому `parent_asset_id` по умолчанию пустая строка `""`.
- Сервис стикербомбинга поддерживает это поле: если `parent_asset_id != ""`, макет считается вырезанным стикером из указанного стикерпака.

## 6. Безопасное сопоставление путей (Path Traversal Protection)

Чтобы избежать уязвимостей выхода за пределы файлового хранилища, сервис проверяет все пути:
```python
from pathlib import Path

def resolve_asset_path(storage_root: Path, rel_folder_path: str, filename: str) -> Path:
    # Очистка путей от опасных последовательностей
    clean_folder = Path(rel_folder_path.lstrip("/\\"))
    target = (storage_root / clean_folder / filename).resolve()
    
    # Гарантируем, что target строго внутри storage_root
    if not target.is_relative_to(storage_root.resolve()):
        raise ValueError(f"Path traversal detected: {rel_folder_path} / {filename}")
    return target
```
Если файл не найден на диске, стикер логируется с предупреждением и исключается из активной выдачи публичного API.
