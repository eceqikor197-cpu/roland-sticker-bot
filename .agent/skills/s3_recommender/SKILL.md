# Этап S3: Вкусовой профиль и рекомендации

## Контекст и правила
- Читай `AGENTS.md`, `docs/DATA_CONTRACT.md` и `docs/PROGRESS.md`.
- Сервер без состояния: профиль вкуса хранится на клиенте (`liked`/`disliked`) и передаётся в запросе.
- Алгоритмический этап: пиши чистыми функциями с высокой детерминированностью при фиксированном seed.
- Работа ведётся в ветке `feature/s3`.

## Архитектура признаков
1. **Уровень A (базовый, без тяжёлых зависимостей):**
   - Вектор признаков макета = нормированная конкатенация:
     - TF-IDF по тегам (вес 0.5)
     - One-hot вектор категории и темы (вес 0.2)
     - Цветовая гистограмма в пространстве HSV/RGB по палитре (вес 0.2)
     - Геометрия: `aspect` и `alpha_coverage` (вес 0.1)
   - Хранение векторов: таблица `asset_features(asset_id PK, vector BLOB)` в `app.db` (массив `float32`).
   - Кэширование матрицы векторов в памяти процесса для быстрого поиска.
   - Команда построения векторов: `python -m sticker_app.build_features`.

2. **Уровень B (опциональный, за флагом `EMBEDDINGS=clip`):**
   - Интерфейс `EmbeddingProvider`.
   - Если флаг выключен или библиотеки не установлены, сервис прозрачно работает на Уровне A.

## Задачи этапа
1. **Команда `python -m sticker_app.build_features`:**
   - Вычисляет векторы для всех макетов и сохраняет их в `app.db`.
   - Описание алгоритма зафиксировать в `docs/RECOMMENDER.md`.

2. **Эндпоинты API:**
   - `GET /api/v1/onboarding/cards?n=12`:
     - Набор из 12 максимально разнообразных по духу стикеров.
     - Алгоритм Farthest-Point Sampling (FPS) по матрице расстояний.
     - Ограничение: не более 2 стикеров из одной темы.
   - `POST /api/v1/taste/profile`:
     - Вход: `{"liked": ["id1", "id2"], "disliked": ["id3"]}`
     - Вычисляет вектор профиля: `normalized(mean(liked) - 0.5 * mean(disliked))`.
     - Возвращает вектор профиля и топ-5 ассоциативных тегов пользователя для UI.
   - `POST /api/v1/recommend`:
     - Вход: `{"profile_vector": [...], "liked": [...], "count": 20, "constraints": {"max_per_topic": 3, "min_unique_topics": 5}}`
     - Косинусное сходство + диверсификация через **Maximal Marginal Relevance (MMR)**:
       $MMR = \arg\max_{D_i \in R \setminus S} [\lambda \cdot Sim(D_i, Q) - (1 - \lambda) \cdot \max_{D_j \in S} Sim(D_i, D_j)]$ при $\lambda = 0.7$.
     - Cold Start: если передано < 2 лайков, подмешивать популярные и разнообразные темы.
     - Исключение уже лайкнутых стикеров по флагу `include_liked=false`.

3. **Оценка и тесты (`tests/app/test_recommender.py` и `scripts/eval_recommender.py`):**
   - Тест на профиль вкуса: у профиля с лайками в теме «Ретро Вейв» в топе выдачи доминирует Ретро Вейв и Киберпанк.
   - Тест MMR: при включении MMR количество уникальных тем в выдаче строго больше, чем при чистом косинусном сходстве.
   - Тест Cold Start: пустой запрос или 1 лайк не вызывает ошибок и отдаёт разнообразный валидный список.
   - Детерминированность: одинаковый входной вектор даёт одинаковый ранжированный список.
   - Скрипт `scripts/eval_recommender.py` выводит метрики (среднее попарное сходство, разнообразие тем, precision@K).

## Критерий готовности
- Все 3 эндпоинта отвечают по контракту на демо-каталоге.
- Уровень A полностью автономен и не требует PyTorch/GPU.
- `docs/RECOMMENDER.md` описывает формулы и веса.
- `python -m pytest -q` и `python -m ruff check .` зелёные.
- Результаты зафиксированы в ветке `feature/s3`, обновлён `docs/PROGRESS.md`.
