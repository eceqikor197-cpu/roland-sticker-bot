# Рекомендательная система и вкусовой профиль (Этап S3)

## 1. Концепция и архитектурные принципы

- **Сервер без состояния (Stateless):** Сервис не хранит профили или историю пользователей. Весь контекст (`liked`, `disliked`, `profile_vector`) хранится на клиенте (localStorage браузера) и передаётся в теле запросов.
- **Двухуровневая архитектура признаков:**
  - **Уровень A (базовый, автономный):** Не требует GPU, PyTorch или тяжёлых нейросетевых зависимостей. Полностью работает на стандартной библиотеке Python и NumPy/SciPy.
  - **Уровень B (опциональный, нейросетевой):** Защищён абстрактным интерфейсом `EmbeddingProvider`. При флаге `EMBEDDINGS=clip` пытается использовать мультимодальный CLIP. Если зависимости отсутствуют, прозрачно откатывается на Уровень A.
- **Баланс релевантности и разнообразия:** Использование алгоритма **Maximal Marginal Relevance (MMR)** для устранения проблемы «пузыря фильтров» (эхо-камеры).

## 2. Архитектура признаков Уровня A

Вектор признаков каждого макета $V \in \mathbb{R}^D$ представляет собой взвешенную конкатенацию четырёх нормализованных блоков:

$$V = \text{L2\_Normalize}\Big( [w_1 \cdot v_{\text{tfidf}}, \; w_2 \cdot v_{\text{topic}}, \; w_3 \cdot v_{\text{color}}, \; w_4 \cdot v_{\text{geom}}] \Big)$$

где $||V||_2 = 1.0$.

### Блоки признаков и веса:

1. **TF-IDF по тегам (вес $w_1 = 0.5$):**
   - Словарь формируется по всем доступным макетам каталога (`usable_in_service = 1`).
   - Сглаженная формула обратной документной частоты:
     $$\text{IDF}(t) = \ln\left(\frac{N + 1}{\text{DF}(t) + 1}\right) + 1.0$$
   - Для макета: $v_{\text{tfidf}}[i] = \text{IDF}(t_i)$ при наличии тега $t_i$.
   - Блок нормализуется по L2-норме и масштабируется на $0.5$.

2. **One-Hot категории и темы (вес $w_2 = 0.2$):**
   - Бинарные индикаторы подкатегории (`category_lvl2`) и темы (`topic_name`).
   - Фиксирует принадлежность к смысловому разделу каталога.
   - Блок нормализуется по L2-норме и масштабируется на $0.2$.

3. **Цветовая HSV-гистограмма по палитре (вес $w_3 = 0.2$):**
   - Анализирует 5 доминирующих HEX-цветов макета из `asset_meta.palette_json`.
   - Конвертация HEX $\to$ RGB $\to$ HSV (оттенок $H \in [0, 1)$, насыщенность $S \in [0, 1]$, яркость $V \in [0, 1]$).
   - 11 корзин гистограммы:
     - 8 корзин оттенка (Hue) при $S \ge 0.15$ (красный, оранжевый, жёлтый, зелёный, циан, синий, фиолетовый, пурпурный).
     - 3 ахроматические корзины при $S < 0.15$: чёрный ($V < 0.25$), белый ($V > 0.80$), серый.
   - Блок нормализуется по L2-норме и масштабируется на $0.2$.

4. **Геометрические пропорции (вес $w_4 = 0.1$):**
   - Вектор размерности 2: $[\text{aspect\_norm}, \; \text{alpha\_coverage}]$.
   - $\text{aspect\_norm} = \text{clamp}(\text{aspect}, 0.2, 5.0) / 5.0$.
   - $\text{alpha\_coverage} \in [0.0, 1.0]$ (доля непрозрачной площади стикера).
   - Блок нормализуется по L2-норме и масштабируется на $0.1$.

### Хранение векторов:
Векторы хранятся в таблице `asset_features` базы данных `app.db` в виде бинарных BLOB-массивов `float32`. Словарь признаков сохраняется в таблице `feature_vocabularies`.
При старте сервера матрица векторов загружается в память процесса, обеспечивая мгновенный расчёт косинусного сходства через скалярное произведение:
$$\text{Sim}(A, B) = A \cdot B$$

## 3. Алгоритмы рекомендаций

### 3.1. Farthest-Point Sampling (FPS) для карточек онбординга
- **Эндпоинт:** `GET /api/v1/onboarding/cards?n=12`
- **Цель:** Отобрать $n$ визуально и тематически максимально контрастных стикеров для первого знакомства с пользователем.
- **Алгоритм:**
  1. Матрица расстояний: $d(u, v) = 1.0 - \text{Sim}(u, v)$.
  2. Начальная точка выбирается детерминированно.
  3. На каждом шаге выбирается кандидат с максимальным расстоянием до уже отобранного множества:
     $$D(x) = \min_{s \in S} d(x, s)$$
  4. Действует ограничение: не более 2 стикеров из одной темы (при малом количестве тем в каталоге лимит равномерно балансируется до $\lceil n / T \rceil$).

### 3.2. Расчёт вкусового профиля
- **Эндпоинт:** `POST /api/v1/taste/profile`
- **Вход:** списки `liked` и `disliked` идентификаторов стикеров.
- **Формула профиля:**
  $$P_{\text{raw}} = \text{mean}(V_{\text{liked}}) - 0.5 \cdot \text{mean}(V_{\text{disliked}})$$
  $$P = \frac{P_{\text{raw}}}{||P_{\text{raw}}||_2}$$
- **Ассоциативные теги:** Для каждого тега вычисляется скор с учётом положительных лайков, штрафа за дизлайки и IDF. Топ-5 тегов с наибольшим положительным весом возвращаются клиенту для визуализации его вкуса.

### 3.3. Maximal Marginal Relevance (MMR) ранжирование
- **Эндпоинт:** `POST /api/v1/recommend`
- **Формула MMR:** На каждом шаге отбора из доступных кандидатов $R \setminus S$ выбирается элемент, максимизирующий:
  $$\text{MMR}(D_i) = \lambda \cdot \text{Sim}(D_i, Q) - (1 - \lambda) \cdot \max_{D_j \in S} \text{Sim}(D_i, D_j)$$
  при $\lambda = 0.7$.
- **Тематические ограничения (Constraints):**
  - `max_per_topic` (по умолчанию 3): предотвращает монополизацию выдачи одной темой.
  - `min_unique_topics` (по умолчанию 5): гарантирует минимальное количество представленных тем в рекомендациях.
- **Холодный старт (Cold Start):**
  - При отсутствии лайков ($\text{count} < 2$) вектор запроса опирается на центроид каталога, а параметр $\lambda$ автоматически снижается до $0.3 \dots 0.5$, форсируя широкую разведку интересов.
- **Исключение просмотренного:** Лайкнутые и дизлайкнутые стикеры исключаются из выдачи при `include_liked=false`.
