Фаза 6: хранилище. Читай AGENTS.md. Делай по шагам, коммит на каждый.

Проблема: user_prefs.json, users_db.json, admin_state.json читаются и перезаписываются целиком под одним глобальным локом; настройки хранятся на пользователя, а не на задание, поэтому два открытых макета влияют друг на друга. Рядом отдельная SQLite в harvester/database.py.

Задачи:
1. Создай модуль storage/ с SQLite (WAL, одно соединение на поток) и таблицами users, prefs, jobs, admin_state. Описание схемы в docs/storage.md.
2. Одноразовый скрипт миграции scripts/migrate_json_to_sqlite.py: читает старые JSON (если есть), переносит в БД, ничего не удаляет, умеет dry-run.
3. Замени вызовы load_json_file/save_json_file для этих данных на функции storage. Интерфейс функций (get_user_prefs, update_user_prefs, record_user_activity, list_all_jobs ...) сохрани, чтобы остальной код не менялся.
4. Параметры макета (размер, кант, растяжение, тираж) сохраняй в записи задания (jobs), а не в prefs пользователя; prefs хранит только значения по умолчанию.
5. Тесты на параллельную запись из нескольких потоков и на миграцию.

Критерий готовности: старые данные переносятся без потерь, тесты зелёные, отчёт по формату AGENTS.md.
