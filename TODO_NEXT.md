## Баги, найденные в Фазе 0 (тесты-заглушки)

### 1. `calculate_nesting_and_price` — ошибочный `a4_fit_qty = 1` для изделий больше формата A4
- **Файл**: `jpeg2eps.py` (строки ~1185–1198)
- **Описание**: При габаритах изделия, превышающих полезное поле листа А4 (200×287 мм), переменные `a4_fit_1` и `a4_fit_2` равны `0`. Из-за использования `max(1, a4_fit_1)` в ветке `else` функция возвращает `a4_fit_qty = 1`, `a4_cols = 1`, `a4_rows = 1`, сообщая пользователю о вместимости 1 шт., хотя изделие на лист физически не помещается.
- **Тест**: `tests/test_pricing.py::test_item_larger_than_a4_should_be_zero` (помечен `xfail`).
- **Решение**: Возвращать `a4_fit_qty = 0`, `a4_cols = 0`, `a4_rows = 0`, если изделие не помещается ни в одной ориентации.

### 2. `calculate_nesting_and_price` — отсутствие отбраковки изделий шире рулона плоттера
- **Файл**: `jpeg2eps.py` (строки ~1155, 1165, 1181)
- **Описание**: Если ширина или обе стороны изделия больше рабочей ширины рулона (например, 1500 мм при ширине 1370 мм и рабочей 1360 мм), расчет `cols_a` дает 0, но из-за `max(1, ...)` устанавливается `cols = 1`. В итоге `used_width_mm` превышает физическую ширину рулона (1510 мм > 1370 мм), и расчет продолжается без предупреждений или ошибок.
- **Тест**: `tests/test_pricing.py::test_item_wider_than_roll_should_fail_or_flag` (помечен `xfail`).
- **Решение**: Добавить явный флаг `fits_roll: bool = False` либо вызывать `ValueError` при невозможности разместить изделие по ширине.

### 3. Падение при импорте `telegram_bot` без установленного токена
- **Файл**: `telegram_bot.py` (строка 81), `harvester/config.py` (строка 60)
- **Описание**: Библиотека `telebot.TeleBot(BOT_TOKEN)` на этапе создания объекта валидирует наличие двоеточия (`Token must contain a colon`). При пустом `PLOTTER_BOT_TOKEN` импорт модуля завершается исключением `ValueError`.
- **Временное решение в тестах**: В `tests/conftest.py` задан фиктивный токен `123456:dummy_test_token`.
- **Полноценное решение**: Запланировано в Фазе 1 (вынос секретов и конфигурации).
